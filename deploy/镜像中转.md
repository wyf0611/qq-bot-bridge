# 国内服务器拉取 NapCat 镜像的中转方案

国内服务器（阿里云等）直连 Docker Hub 通常超时拉不动。方案：在海外 VPS 拉镜像 → 打包 → 传回国内服务器导入。

## 1. 海外 VPS 拉取并打包

```bash
docker pull mlikiowa/napcat-docker:v4.18.28
docker save mlikiowa/napcat-docker:v4.18.28 | gzip > /tmp/napcat.tar.gz
gzip -t /tmp/napcat.tar.gz   # 校验完整性
md5sum /tmp/napcat.tar.gz    # 记下 md5，待会对比
```

## 2. 海外 VPS 用 nginx 提供下载（要支持 Range，aria2 多连接才有效）

```bash
apt-get install -y nginx
cat > /etc/nginx/conf.d/files.conf <<'EOF'
server {
    listen 8080;
    root /tmp;
    autoindex on;
}
EOF
nginx -t && systemctl reload nginx
```

> 注意：`python3 -m http.server` **不支持 Range**，aria2 会退化成单连接；必须用 nginx。

## 3. 国内服务器 aria2 多连接下载（约 8MB/s，单连接只有 ~200KB/s）

```bash
apt-get install -y aria2
aria2c -x 16 -s 16 -k 1M --file-allocation=none -d /tmp -o napcat.tar.gz http://<海外VPS-IP>:8080/napcat.tar.gz
```

## 4. 校验 + 导入

```bash
md5sum /tmp/napcat.tar.gz    # 与海外那台的 md5 对比，一致再继续
gunzip -c /tmp/napcat.tar.gz | docker load
docker images | grep napcat  # 看到 mlikiowa/napcat-docker:v4.18.28 即成功
```

---

## 为什么这么折腾

- 国内服务器直连 `registry-1.docker.io`（Docker Hub）会被墙/超时。
- 免费镜像源（DaoCloud、1ms.run 等）不稳定，常卡在「Pulling fs layer」不动。
- 跨境单条连接被限速到 ~200KB/s，aria2 开 16 连接能到 8MB/s（GFW 是按连接限速的）。
- 镜像本身约 2.1GB，压缩后约 560MB。
